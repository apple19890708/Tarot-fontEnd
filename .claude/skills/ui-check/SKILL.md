# 畫面交付前自檢

每一條都來自這個專案實際出過的問題（括號裡是當時的例子）。改到哪一類就檢查哪一類，**沒改到的類別寫「不適用」，不要跳過不講**。

## 0. 本專案的 UI 慣例（寫畫面前先看）

這些是固定作法，新畫面直接照用；下面 1～7 是交付前要逐類確認的事。

- **分頁和篩選的「選中」用不同顏色**：換頁的分頁列（清單、股市各分頁、時間範圍）選中用金色（`border-accent-hue bg-selected text-on-selected`）；同一頁裡的篩選、排序、開關按鈕選中用中性色（`border-ink-soft/60 bg-tint/10 text-ink`），不要也用金色。兩排上下疊在一起時都用金色，分不出哪一排是換頁、哪一排是篩選（例：自訂股票追蹤的「清單」分頁和下面的「市場／排序」，2026-11-08）。
- **顏色用語意色（日夜模式）**：新寫或改到的畫面，顏色用 `style.css` 的語意色（`bg-surface`、`bg-raised`、`border-line`、`border-frame`、`text-ink`／`ink-soft`／`ink-muted`、`text-accent`、`text-up`／`down`、`text-info`／`warn`／`danger`……），不要再直接寫 `bg-[#0f1526]`、`text-stone-300`、`border-white/10`、`text-amber-100`。要透明度時用色相：`bg-tint/5`（取代 `bg-white/5`）、`border-accent-hue/40`（取代 `border-amber-200/40`）、`danger-hue`、`ok-hue`、`info-hue`。陰影用 `var(--c-shade)`。漲跌用 `up`／`down`（`text-up`、`bg-up-hue/10`、`text-up-ink`），錯誤用 `danger`，往下壓暗用 `bg-sink/20`（取代 `bg-black/20`）。**圖表顏色**一律從 `CHART_COLORS`（`src/lib/chartPalette.ts`）拿、寫在 computed 或函式裡，不要存成模組層級常數，否則切換日夜模式時圖表不會換色（例：`MarketAssetHistory` 的大盤色原本是常數）。**沒有面板當底、直接疊在像素夜景上的字**（首頁標題與步驟列）要加 `on-scene`：夜景不分日夜，這些區塊固定用黑夜的顏色，否則白天會變成深字壓在夜空上。黑夜的值＝原本的顏色，白天模式（水晶球選單切換）才看得出差別；交付前兩種模式都要看。計畫與色票見 `doc/v18-day-mode-plan.md`（例：水晶球選單 `FloatingMenu`）。

- **載入中一律用 Skeleton**：新頁面、新分頁、新區塊只要會載入資料，載入中都要用 `SkeletonBlock` 畫出和載入後版面同形狀的骨架（卡片數、欄數、列數、按鈕列對得上），不要只放一兩條通用長條或只寫「載入中…」。要等資料才出現的元素（例如期間切換按鈕）也要先放同尺寸的佔位，避免版面跳動。範例見 `src/components/market/MarketHitRate.vue`。
- **更新按鈕要防呆**：股票相關頁面的「更新」「重新查詢」「開始篩選」「送測試通知」這類會打 API 的按鈕，載入中要停用，按完後還要冷卻一段時間（用 `src/lib/useCooldown.ts`，按鈕上顯示剩餘秒數），避免使用者一直按。`useCooldown(秒數, key)` 一定要給 key，冷卻會記在 localStorage，重新整理頁面也接著倒數。目前冷卻：大盤概況與更新報價 30 秒、選股 6 秒、測試通知 15 秒。
- **依月份看的股利類資料用「月份小卡格子」**：12 個月排成格子（手機 2 欄、平板 3 欄、桌機 4 欄），卡片放月份、合計、代號（實線＝確定、虛線＝推估，最多幾個再寫「+N」），點卡片跳出小彈窗列這個月每一檔的日期與細節；不要一個月一列的長表格（太佔空間），也不要同一份資料再做一個月曆。格子裡股票一律放代號，名稱截斷後看不懂。範例 `MarketIncome.vue` 的每月股利＋`IncomeMonthDialog.vue`，哪幾檔的判斷在 `src/lib/incomeMonthEntries.ts`（例：每月股利表一個月一列太佔空間，改成小卡並取代股利月曆，2026-11-10）。
- **開／關、勾選類的設定一律用 checkbox**：用 `src/components/CheckboxField.vue`（`v-model`，或 `:model-value`＋`@update:model-value` 自己處理），不要用「按一下切換外框深淺」的按鈕當開關，選取與未選取看不出差別；也不要自己寫原生 checkbox 配 `accent-amber-*`（白天模式顏色不對）。多選（例如一檔放進哪些清單）也用它。「切換模式」的動作按鈕（調整順序／完成排序）和單選的一排選項不算。（例：股利月曆的「除息前一個交易日提醒我」是外框按鈕，使用者回報看不出有沒有開，2026-11-10；同一次把支撐壓力線、股市總覽的區塊顯示、清單勾選、選股條件、只看與我追蹤相關一起換掉）
- **會隨股票數量變長的列表要分頁**：用 `src/lib/usePaged.ts`＋`src/components/ListPager.vue`（每頁 5／10／15／20／50，每個列表各自記住筆數；5 筆以下不顯示分頁列）。卡片和表格兩種檢視共用同一頁的資料。（例：股利獲利與預測的填息追蹤、每檔持股、應收股利、還沒買的、預估準不準、年度報表明細，2026-11-10；股市總覽的自選清單與推薦股票、自訂股票追蹤，2026-11-11——`DashboardWatchList` 用 `pageKey` 分開記筆數、`resetKey` 在換清單或篩選時回第 1 頁）。換分類、換清單時要回第 1 頁，不然可能停在新清單不存在的頁數或中間頁。
- **桌機不要「一檔一張卡片、卡片裡再一張表」並排**：高低不齊、留大片空白。改成一檔一列的總覽表，趨勢用一排小色塊表示，點一列才展開明細；手機再用收合卡片。（例：填息追蹤第一版兩欄卡片，使用者說太醜，2026-11-10）同理，摘要卡只有一兩張時桌機改成表格：一個市場一列、指標排成欄（例：股利獲利與預測的台股摘要卡在桌機只佔左邊三分之一，2026-11-10）。
- **每一筆都一樣的說明放進 `HelpTip`**：清單或彈窗裡每一項都重複同一句解釋（例如「日期和金額都是推估：…」），改成在標籤旁放一個「?」，說明寫進 `marketGlossary.ts`，不要每一項印一次（例：每月股利彈窗，2026-11-10）。
- **輔助性的長區塊要能收合**：會隨資料變長、但不是每次都要看的區塊（例如應收股利對照），標題做成可以點的收合開關（▸ 旋轉），用 `src/lib/useStoredToggle.ts` 記住開或關；收起來時標題列仍顯示筆數，主要動作按鈕（全部帶入）也留在標題列（例：應收股利對照太佔空間又不能關，2026-11-10）。
- **表格一律用 `src/components/DataTable.vue`，不要自己寫 `<table>`**：外框與橫向捲動、表頭淡底與字級、儲存格內距、列分隔線、**所有欄位（含數字）靠左**、th 不加粗都由它統一。一般資料表用預設樣式（`table-class="min-w-[..rem]"` 給手機捲動寬度）；卡片裡的小表、展開的明細用 `variant="compact"`；外框要和表格下面的內容框在一起時用 `frameless`、外層自己包框。**每列第一欄自動固定在左邊**（手機左右捲時列標題不跟著捲走，2026-11-11 使用者要求），不用自己加；列本身有底色時（滑過、展開、強調）要用 `src/lib/table.ts` 的 `ROW_TINT`／`ROW_HOVER`／`ROW_HOVER_STRONG`／`ROW_SINK`，固定欄才會跟著同色，直接寫 `bg-tint/5` 會出現一塊不同色的方塊；跨欄（colspan）的格子不固定。不用 DataTable 的表格（`AdminUsers` 和紙主題）要自己加固定欄與底色。儲存格只寫顏色、字重、`whitespace-nowrap` 這類內容相關的 class；要例外（例如箭頭欄 `px-2`）直接加 class 就會蓋過（共用規則包在 `:where()` 裡，權重 0）。（例：填息追蹤的數字靠右、其他欄靠左，各表格內距、表頭樣式都不一樣，使用者要求全部靠左並統一成共用元件，2026-11-11；`AdminUsers` 是像素和紙主題，例外保留原樣但也靠左）
- **不要用程式改寫搜尋框（`StockSearchInput`）的文字**：它把任何文字變動都當成使用者在打字，會拿新文字去搜尋；改成搜不到的字串（例如「名稱 代號」）之後，一點輸入框就跳出「找不到符合的台股」。查到結果要顯示名稱，放在輸入框下面另一行。（例：存股試算的自選一檔，查完把輸入框改成「群益台灣精選高息 00919」，2026-11-11）
- **表格的股票欄一律用 `src/components/StockNameCell.vue`**：名稱在上、代號在下，名稱太長截斷（滑過看全名）；要點名稱開詳細時給 `action`（按鈕的說明文字）並接 `@open`；代號後面的補充（「．季配」「．沒持股」「．上櫃」）放預設插槽。不要再寫「名稱 代號」同一行。（例：填息追蹤是同一行、長名稱換行後代號掉到下一行，其他表格又是上下排，使用者要求統一名稱在上、代號在下，2026-11-11）
- **逐筆的「預估 vs 實際」這類比較用表格，不用長條圖**：一次比較一列，欄位直接放數字（預估、實際＋日期、落差、準確率），一眼就看得到差多少；長條圖每檔一張，要滑過去才看得到數字。（例：股利獲利與預測的「預估準不準」原本每檔一張長條圖，使用者要求改成表格，2026-11-11）
- **表格裡不要展開一整列長內容**：在 `overflow-x-auto` 的表格裡用跨欄（colspan）列展開一段文字或算式，展開時會把表格撐寬、冒出橫向捲軸，整塊上下抖動。短的內容直接放在表格下面一直顯示；長的明細用彈窗（例：股利摘要表的「報酬怎麼來的」，2026-11-10）。
- **長頁面要有回到頂端**：股票相關的頁面（股市追蹤、股市諮詢結果）放 `BackToTop`，往下捲超過一個畫面高就出現。
- **移除、刪除一律先確認**：用 `src/lib/confirm.ts` 的 `await confirmDialog({ title, message, confirmText, danger: true })`（畫面是 `ConfirmDialog.vue`，掛在 `App.vue`），不要用 `window.confirm`，也不要自己做「再按一次確定」。只刪表單裡還沒儲存的一列不用確認。
- **指標旁放說明**：股市指標名稱旁用 `src/components/HelpTip.vue`（圓圈「?」），說明文字集中在 `src/lib/marketGlossary.ts`；新增指標時一起補說明。
- **彈窗開著時背景不能捲動**：彈窗元件呼叫 `src/lib/useScrollLock.ts` 的 `useScrollLock()`。
- **按鈕字級**：新按鈕用 `text-button`（見下方 RWD 字級規範）；既有的 `text-[14px]` 改到時再換。`style.css` 的全域元素樣式一律放進 `@layer base`，否則會蓋掉 Tailwind 的 class。
- **下拉選單一律用 `SelectField.vue`**，不要用原生 `<select>`：原生的展開清單是作業系統畫的，樣式和游標都改不了（深底深字看不見、滑過是箭頭不是手指）。依位置選 `variant`：占卜頁 `glass`、我的紀錄 `washi`、股市頁 `pixel`；旁邊已有說明文字時加 `hide-label`。
- **整頁捲動一律用 `src/lib/motion.ts` 的 `smoothScrollTo(top)`**（回到頂端、跳到段落、捲到某一列），不要用 `window.scrollTo({ behavior: 'smooth' })`：原生的平滑捲動在長頁面幾乎瞬間到頂，看起來沒有動畫。彈窗內部自己的捲動區可以用 `scrollIntoView`。
- **我的紀錄的清單**一律用 `RecordListShell`（外框）＋`RecordIndex`（索引標籤清單），新的紀錄類別照塔羅、股票分析、財經新聞的寫法接上。
- **更新類按鈕的樣子**：股市頁的「更新」「重試」一律用 `src/components/RefreshButton.vue`（按下、更新中、已更新、冷卻進度條都做好了）；其他會打 API 的按鈕至少要有 `active:` 按下效果。
- **文字不要用暗灰色**：深色底上的說明文字、欄位標籤最暗用 `text-stone-300`，不要用 `text-stone-400`／`500`／`600`（看不清楚）。要和數值區分就靠顏色而不是調暗，例如持股的「均價」用 `text-amber-200`。字級照下面的「RWD 字級規範」。
- **AI 的長篇內容要整理過，不是把資料倒給使用者**：數據類的段落（情境、行情、技術面、方向）用「表格＋一句粗體結論」，不要整段文字夾一堆數字。表格由後端提示詞規定表頭與固定用詞（`../Tbackend/src/services/narrationService.js`），前端一律用 `src/lib/aiMarkdown.ts` 的 `renderAiMarkdown()`＋`AI_TABLE_CLASS` 顯示：整格是「偏多／偏空／觀望／中性」「壓力／現價／支撐」時上色、純數字格不換行。表格最多三欄（手機放得下），固定用詞改了要前後端一起改（例：股市諮詢的情境與操作、技術面判斷是整段文字，使用者要求整理成表格，2026-11-12）。
- **股市文字要白話**：使用者多半沒學過技術分析。畫面上的標題、欄位名稱、說明一律用白話（年化→平均每年、最大回落→最慘時從高點跌了、勝率→幾成有賺、買進持有→買了一直抱著、樣本少→次數太少），專有名詞（均線、RSI、KD…）旁放 `HelpTip`。後端產生的規則文字太專業時，請後端另外給白話欄位（例如策略的 `plain`），前端不自己改寫。
- **RWD 字級規範**：字級一律用下面的語意 class，大小由 `src/style.css` 的 `--fs-*` 變數依螢幕寬度自動切換，不要再寫 `text-[11px]`、`text-xs`、`md:text-base` 這類固定或加前綴的字級。三級斷點：**m** 600px 以下（手機）、**l** 601～1919px（以 1440 為設計基準，平板也算這級）、**xl** 1920px 以上。

  | class | 用途 | m | l | xl |
  |---|---|---|---|---|
  | `text-display` | 頁面大標、主要價格大字 | 24 | 32 | 40 |
  | `text-title` | 區塊標題 | 18 | 22 | 26 |
  | `text-subtitle` | 卡片標題、股票名稱、彈窗標題 | 16 | 18 | 20 |
  | `text-body` | 內文、資訊欄位、數字、標籤、AI 文字 | 14 | 16 | 18 |
  | `text-caption` | 註腳、日期、圖表說明、免責聲明 | 13 | 14 | 16 |
  | `text-button` | 按鈕 | 14 | 14 | 16 |

  - 最小字級 13px（`text-caption` 的手機值）；不再新增 12px 以下的文字。
  - 行高已內建在 class 裡，一般不用另外加 `leading-*`。
  - 例外：`font-pixel` 的像素小標（`text-[12px]` 這類，要用 12 的倍數才方正）維持原本寫法；像素字型的按鈕照樣用 `text-button`。
  - 固定寬度的文字欄（標籤、日期這類短字）寬度用 `em`（例如 `w-[2.5em]`）＋`whitespace-nowrap`，才會跟著字級變寬；寫死 `w-8` 會讓「偏空」在 16px 以上斷成兩行（判斷依據曾經這樣）。數字欄（例如追蹤清單一列裡的現價、漲跌、損益）字放大後也要確認放得下，1920 以上不夠就加 `min-[1920px]:w-*`；Tailwind 內建的 `xl:` 是 1280，不是這裡的 xl。
  - 既有畫面還有很多 `text-xs`／`text-sm`／`text-[11px]`，改到哪一塊就順手換成語意 class；範例見 `MarketHoldings.vue` 的持股區塊。已換完：股市追蹤頁外框、自訂追蹤（含持股、群組、事件、新聞）、個股分析彈窗與 `MarketPanel` 全套（行情、籌碼估值、回測、操作建議）、大盤概況、財經新聞（含新聞重點與 AI 影響分析彈窗）、選股、參考命中、價位提醒（含推播設定）、我的紀錄（外框、和紙清單 `RecordIndex`／`RecordListShell`、股票分析、財經新聞分析；塔羅紀錄內容是 `StepResult`，跟占卜頁一起換），以及共用的 `HelpTip`、`RefreshButton`、`SectionJumpMenu`。

## 1. 每個操作都有看得到的回饋（手機沒有 hover）

- 會打 API 的按鈕要有：可按、按下（`active:` 下沉）、進行中（轉圈＋「…中」）、結束（成功提示或失敗訊息）四種樣子（股市頁用 `RefreshButton`，見第 0 節）。
- **一定要走一次「已經有資料時再按一次」的路徑**。`load()` 常常只在沒資料時才設 `loading`（畫面不想換成骨架），這時按鈕要自己有 `refreshing`（財經新聞「更新」按下去沒反應，就是這樣）。
- 只有 `hover:` 的效果在手機上等於沒有；每個可點的元素都要有 `active:` 或狀態變化。
- 停用、冷卻要看得出原因（剩餘秒數、提示文字），不能只是變淡。
- **狀態切換時按鈕的大小、位置不能變**：文字會換（「更新 → 更新中… → 已更新 → 更新（29）」）就先保留最寬那個的寬度（各狀態文字疊在同一格，見 `RefreshButton`）；「按下去」的位移只能在 `active:` 那一下，不能在載入、冷卻時一直保持，否則和旁邊的按鈕錯開。同一列的按鈕高度要一致（`RefreshButton` 與 `EditToggleButton` 都是 `h-8`）。例：股市總覽按「更新」後，按鈕變寬又往右下沉 3px，和「客製化區塊」對不齊。
- 長時間的請求（AI 串流）不能永遠停在「…中」：串流一律用 `api.ts` 的 `ndjsonEvents()`（有心跳判斷、太久沒資料就丟 `StreamStalledError`）；失敗時保留已經產生的內容，並把原因顯示在使用者看得到的地方（AI 分析產到一半卡住、一直顯示「分析中…」）。

## 2. 手機寬度（以 375px 想一遍）

- 照 class 推想 375px 時的排列：`flex-wrap` 換行後每個元素落在哪、長標題怎麼斷、按鈕會不會被擠掉。
- **整頁不能比畫面寬**：在 375／739／1280 寬度、各種檢視（卡片／表格）下，`document.documentElement.scrollWidth` 都要等於畫面寬度。頁面一變寬，手機會把整頁縮小，看起來像「版型靠左、右邊空一塊」。常見原因：捲動框（`overflow-x-auto`）裡的絕對定位元素（`sr-only`、提示泡泡）不會被裁切，除非捲動框本身是 `relative`。（例：填息追蹤表頭的 `sr-only`「展開」在表格變寬後跑到框外，把頁面撐到 848，2026-11-11；`DataTable` 已加 `relative`）
- 數字、金額欄固定寬度＋`tabular-nums`，**不能因為某欄沒有值就位移**（沒設張數時數字跑位）。表格裡一律靠左（見「本專案的 UI 慣例」的 `DataTable`）。
- 篩選列的勾選框、開關換行後不能孤零零掉在奇怪的位置（「只看與我追蹤相關」的位置）。
- 點擊目標高度約 32px 以上；並排的同類按鈕寬高一致（移動清單按鈕大小不一）。
- **格線裡放圖表、表格這類會撐寬的東西**：手機那一級要明寫 `grid-cols-1`（只寫 `xl:grid-cols-2` 時，手機的欄寬照內容撐開），卡片本身加 `min-w-0`。否則整張卡片比螢幕寬、右邊被切掉（股市總覽的股票卡片，K 線圖把欄撐開，價格與「最高」被切掉，2026-11-08）。`<input>` 也算：它有預設寬度（約 20 字），放在 flex 列裡要加 `w-0 flex-1`（例：存股試算「一開始有／每月投入」那幾行，手機上單位「元」被切掉，2026-11-11）。
- **`DataTable` 第一欄預設固定且不換行**：第一欄放的是一整句說明（不是短名稱）時，要在那些格子加 `whitespace-normal min-w-[8em]` 讓它換行，否則整張表被撐寬、數字欄被推出卡片；表格放在淡底卡片（`bg-tint/5`）裡時，卡片要用 `ROW_TINT`，固定欄才不會是一塊比較深的方塊。（例：歷史回測與模型的策略卡片，「加上停損」那列的說明不換行，手機上照規則／一直抱著兩欄被擠出去，2026-11-12）
- **`DataTable` 其他欄預設會換行**：一格裡是兩個短標籤或數字（「偏空 信心中」、日期、價格）時，旁邊的長欄（股票名稱）會把它擠成兩行。整張都是短字的表，用 `table-class="[&>tbody>tr]:whitespace-nowrap"` 整列不換行、讓表格左右捲；只有個別短欄就在那幾格加 `whitespace-nowrap`。交付前推想 1024 與 841 寬度（例：參考命中的紀錄表「建議」欄在 841 寬被擠成兩行，2026-11-12）。
- 不換行（`whitespace-nowrap`）的名稱一定要配最大寬度＋`truncate`＋`title` 看全名，寬度用 `em`；用美股英文全名測一次。例：表格的商品欄固定在左邊，「Micron Technology, Inc.」把它撐到半個手機寬，其他欄被擠出畫面。

## 3. 彈出層（下拉、說明框、彈窗、浮動選單）

- 選了選項就關閉下拉；點外面、按 Esc 也要關；巢狀時 Esc 只關最上面那層（選單的 Esc 不能連彈窗一起關）。
- 彈窗呼叫 `useScrollLock()`，背景不能捲（新聞彈窗背景還能捲）。
- 彈窗有自己的捲動區時，全站的浮動元件（水晶球、回到頂端）管不到，要在彈窗裡自己放。
- 浮動說明框：頁面捲動、視窗改變大小時要跟著重新定位；說明框裡面捲動、點擊不能讓它關掉（HelpTip 拖曳就消失）。
- 全站浮動元件只出現在用得到的頁面（水晶球只該在塔羅結果與我的紀錄）。

## 4. 同一份資料在兩個地方顯示要一致

- 卡片與彈窗、列表與詳細頁的標籤、數量、名稱，要來自**同一個欄位或同一個後端計算**，不要兩邊各算一次（卡片有台積電、彈窗卻沒有）。
- 篩選器旁的計數要用和篩選本身**同一個條件**計算（「只看與我追蹤相關」永遠是 0）。
- 改完挑一筆實際資料，沿著兩條顯示路徑各走一遍，確認結果相同。
- **KeepAlive 分頁顯示別的分頁會改的資料時，切回來（`onActivated`）要重抓**，不能只靠「抓過了」的旗標；重抓時舊資料先留著，不換回骨架，並用 request id 丟掉過期回應（股市總覽的自選清單只抓一次，在自訂股票追蹤刪掉股票後切回來還在，要整頁重新整理才消失）。追蹤清單用 `src/lib/watchlistSync.ts` 的 `watchlistVersion`：改清單的 API 在 `api.ts` 包 `watchlistMutation()` 就會自動加版本號，分頁切回來比對版本號、或開著時 `watch(watchlistVersion)` 重抓（範例：`MarketOverview`、`MarketIncome`）。新增會改清單的 API 一定要包。

## 5. 狀態要撐得過重新整理

- 冷卻有沒有給 key（沒給的話重新整理後冷卻就消失）。
- 新增的展開／收合、選取的分頁、篩選條件：明確決定要不要記住，記的話用 localStorage 並包 try/catch。

## 6. 版面層級與一致性

- 從屬關係要用縮排、外框或字級看得出來，不同層級不能長得一樣（群組和市場兩層同樣式，看不出上下關係）。
- **一個區塊的結果不要偷偷沿用另一個區塊的設定**：看的人只看得到眼前這一塊，「都用上面的設定」要往上找、還分散在好幾處。功能不同的區塊各自放自己的條件（用上下分隔線分開），各自記住；真的要共用時，至少在結果旁把用到的值列出來。（例：存股試算的「比較兩檔」原本沿用上面試算的金額、年數、通膨、殖利率基準，使用者問「上面的設定是哪裡」，改成比較自己一套條件，2026-11-11）
- 數量不固定的標籤要截斷＋「更多（+N）」，不要讓一張卡被撐爆。
- **一列有好幾欄數字或標籤時要有欄位標題**：標題列的寬度、間距、內距（含外框寬度）照抄資料列，每個斷點都要對齊；手機藏起來的欄，標題也一起藏。例：自訂追蹤收合的一列只有數字（98.4、+6.38%、+40,299），看不出哪個是現價、漲跌、損益（後來整個改用股市總覽的卡片／表格 `DashboardWatchList`，表格本身有標題）。股票清單優先用 `DashboardWatchList`（卡片／表格切換），不要再做一種新的列。
- **把元件搬到另一個地方重用時，連它的入口一起帶過去**：有些元件的開關放在外層（例如 `MarketHoldings` 只負責「顯示／編輯」兩種畫面，「編輯持股」按鈕在 `MarketWatchlist` 那一層），只搬元件本身會變成看得到、改不了。重用前先找原本的呼叫端，看 `v-model:*`、`@saved` 這類由外層控制的東西有沒有都接上。（例：股利獲利與預測的「編輯持股」彈窗沒有進入編輯的按鈕，只能改清單、不能改買賣筆數，2026-11-12）
- 同類元件（按鈕、標籤）尺寸一致；新加的全域 CSS 有沒有放進 `@layer base`（曾經整站按鈕字級失效）。
- 第 0 節的慣例都有照做：刪除有確認、新指標有說明、長頁面有回到頂端、會載入的區塊有骨架。

## 7. 文字與字型

- 解讀、分析文字只顯示後端的 `text`，前端不組句子。
- 新增用到 `font-pixel` 的文字後，比對 `node scripts/pixel-font-chars.mjs` 改前改後的字集，有新字就照腳本開頭的指令重新產生字型子集。
