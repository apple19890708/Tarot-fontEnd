# 畫面交付前自檢

每一條都來自這個專案實際出過的問題（括號裡是當時的例子）。改到哪一類就檢查哪一類，**沒改到的類別寫「不適用」，不要跳過不講**。

## 0. 本專案的 UI 慣例（寫畫面前先看）

這些是固定作法，新畫面直接照用；下面 1～7 是交付前要逐類確認的事。

- **載入中一律用 Skeleton**：新頁面、新分頁、新區塊只要會載入資料，載入中都要用 `SkeletonBlock` 畫出和載入後版面同形狀的骨架（卡片數、欄數、列數、按鈕列對得上），不要只放一兩條通用長條或只寫「載入中…」。要等資料才出現的元素（例如期間切換按鈕）也要先放同尺寸的佔位，避免版面跳動。範例見 `src/components/market/MarketHitRate.vue`。
- **更新按鈕要防呆**：股票相關頁面的「更新」「重新查詢」「開始篩選」「送測試通知」這類會打 API 的按鈕，載入中要停用，按完後還要冷卻一段時間（用 `src/lib/useCooldown.ts`，按鈕上顯示剩餘秒數），避免使用者一直按。`useCooldown(秒數, key)` 一定要給 key，冷卻會記在 localStorage，重新整理頁面也接著倒數。目前冷卻：大盤概況與更新報價 30 秒、選股 6 秒、測試通知 15 秒。
- **長頁面要有回到頂端**：股票相關的頁面（股市追蹤、股市諮詢結果）放 `BackToTop`，往下捲超過一個畫面高就出現。
- **移除、刪除一律先確認**：用 `src/lib/confirm.ts` 的 `await confirmDialog({ title, message, confirmText, danger: true })`（畫面是 `ConfirmDialog.vue`，掛在 `App.vue`），不要用 `window.confirm`，也不要自己做「再按一次確定」。只刪表單裡還沒儲存的一列不用確認。
- **指標旁放說明**：股市指標名稱旁用 `src/components/HelpTip.vue`（圓圈「?」），說明文字集中在 `src/lib/marketGlossary.ts`；新增指標時一起補說明。
- **彈窗開著時背景不能捲動**：彈窗元件呼叫 `src/lib/useScrollLock.ts` 的 `useScrollLock()`。
- **按鈕字級**：按鈕統一 `text-[14px]`。`style.css` 的全域元素樣式一律放進 `@layer base`，否則會蓋掉 Tailwind 的 class。
- **下拉選單一律用 `SelectField.vue`**，不要用原生 `<select>`：原生的展開清單是作業系統畫的，樣式和游標都改不了（深底深字看不見、滑過是箭頭不是手指）。依位置選 `variant`：占卜頁 `glass`、我的紀錄 `washi`、股市頁 `pixel`；旁邊已有說明文字時加 `hide-label`。
- **整頁捲動一律用 `src/lib/motion.ts` 的 `smoothScrollTo(top)`**（回到頂端、跳到段落、捲到某一列），不要用 `window.scrollTo({ behavior: 'smooth' })`：原生的平滑捲動在長頁面幾乎瞬間到頂，看起來沒有動畫。彈窗內部自己的捲動區可以用 `scrollIntoView`。
- **我的紀錄的清單**一律用 `RecordListShell`（外框）＋`RecordIndex`（索引標籤清單），新的紀錄類別照塔羅、股票分析、財經新聞的寫法接上。
- **更新類按鈕的樣子**：股市頁的「更新」「重試」一律用 `src/components/RefreshButton.vue`（按下、更新中、已更新、冷卻進度條都做好了）；其他會打 API 的按鈕至少要有 `active:` 按下效果。

## 1. 每個操作都有看得到的回饋（手機沒有 hover）

- 會打 API 的按鈕要有：可按、按下（`active:` 下沉）、進行中（轉圈＋「…中」）、結束（成功提示或失敗訊息）四種樣子（股市頁用 `RefreshButton`，見第 0 節）。
- **一定要走一次「已經有資料時再按一次」的路徑**。`load()` 常常只在沒資料時才設 `loading`（畫面不想換成骨架），這時按鈕要自己有 `refreshing`（財經新聞「更新」按下去沒反應，就是這樣）。
- 只有 `hover:` 的效果在手機上等於沒有；每個可點的元素都要有 `active:` 或狀態變化。
- 停用、冷卻要看得出原因（剩餘秒數、提示文字），不能只是變淡。
- 長時間的請求（AI 串流）不能永遠停在「…中」：串流一律用 `api.ts` 的 `ndjsonEvents()`（有心跳判斷、太久沒資料就丟 `StreamStalledError`）；失敗時保留已經產生的內容，並把原因顯示在使用者看得到的地方（AI 分析產到一半卡住、一直顯示「分析中…」）。

## 2. 手機寬度（以 375px 想一遍）

- 照 class 推想 375px 時的排列：`flex-wrap` 換行後每個元素落在哪、長標題怎麼斷、按鈕會不會被擠掉。
- 數字、金額欄固定寬度或靠右＋`tabular-nums`，**不能因為某欄沒有值就位移**（沒設張數時數字跑位）。
- 篩選列的勾選框、開關換行後不能孤零零掉在奇怪的位置（「只看與我追蹤相關」的位置）。
- 點擊目標高度約 32px 以上；並排的同類按鈕寬高一致（移動清單按鈕大小不一）。

## 3. 彈出層（下拉、說明框、彈窗、浮動選單）

- 選了選項就關閉下拉；點外面、按 Esc 也要關；巢狀時 Esc 只關最上面那層（選單的 Esc 不能連彈窗一起關）。
- 彈窗呼叫 `useScrollLock()`，背景不能捲（新聞彈窗背景還能捲）。
- 彈窗有自己的捲動區時，全站的浮動元件（水晶球、回到頂端）管不到，要在彈窗裡自己放。
- 浮動說明框：頁面捲動、視窗改變大小時要跟著重新定位；說明框裡面捲動、點擊不能讓它關掉（HelpTip 拖曳就消失）。
- 全站浮動元件只出現在用得到的頁面（水晶球只該在塔羅結果與我的紀錄）。

## 4. 同一份資料在兩個地方顯示要一致

- 卡片與彈窗、列表與詳細頁的標籤、數量、名稱，要來自**同一個欄位或同一個後端計算**，不要兩邊各算一次（卡片有台積電、彈窗卻沒有）。
- 篩選器旁的計數要用和篩選本身**同一個條件**計算（「只看與我追蹤相關」永遠是 0）。
- 改完挑一筆實際資料，沿著兩條顯示路徑各走一遍，確認結果相同。

## 5. 狀態要撐得過重新整理

- 冷卻有沒有給 key（沒給的話重新整理後冷卻就消失）。
- 新增的展開／收合、選取的分頁、篩選條件：明確決定要不要記住，記的話用 localStorage 並包 try/catch。

## 6. 版面層級與一致性

- 從屬關係要用縮排、外框或字級看得出來，不同層級不能長得一樣（群組和市場兩層同樣式，看不出上下關係）。
- 數量不固定的標籤要截斷＋「更多（+N）」，不要讓一張卡被撐爆。
- 同類元件（按鈕、標籤）尺寸一致；新加的全域 CSS 有沒有放進 `@layer base`（曾經整站按鈕字級失效）。
- 第 0 節的慣例都有照做：刪除有確認、新指標有說明、長頁面有回到頂端、會載入的區塊有骨架。

## 7. 文字與字型

- 解讀、分析文字只顯示後端的 `text`，前端不組句子。
- 新增用到 `font-pixel` 的文字後，比對 `node scripts/pixel-font-chars.mjs` 改前改後的字集，有新字就照腳本開頭的指令重新產生字型子集。

## 回報格式

最後的訊息要附上：

- **已檢查**：哪幾類、怎麼確認的（例如「推想 375px：篩選列換成兩行，勾選框在第二行靠左」）。
- **這裡無法驗證**：需要真機或實際操作才能確認的項目（例如 iOS 的按下效果、實際動畫），請使用者看哪裡、怎麼操作。沒驗證到的不說「好了」。
