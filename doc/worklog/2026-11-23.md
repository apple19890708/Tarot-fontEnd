# 工作週記（前端）2026-11-23 ～ 2026-11-29

## 2026-11-25

v27「靜謐花園雷諾曼」前端，計畫書在後端 `doc/v27-lenormand-plan.md`。後端的回應形狀照計畫書 3-12（抽牌）、3-13（紀錄）、3-14（AI 解讀），新欄位一律設成可選，線上若還是舊版後端，對應的畫面不顯示或退回原本的行為。

### 權限與入口（階段 1F）
- 型別 `AuthUser`／`AdminUser` 加 `lenormandAccess?`；`session.ts` 加 `canUseLenormand`（admin 或被開通），由 `auth.ts` 轉出。
- 新路由 `/lenormand`，`meta.lenormand` 由 `router.beforeEach` 擋：沒權限回首頁。
- 會員管理頁：權限開關從 AI／股市加成三個（雷諾曼），統計卡、篩選、操作紀錄文字跟著加。後端沒有這個欄位時，那一格顯示「後端尚未支援」，不給按（按了只會 404）。
- 頂欄右上的「占卜」改成選單（`DivinationMenu`）：塔羅／雷諾曼。只有能用雷諾曼的人看到選單，其他人（含訪客）維持原本的單一連結。操作照會員選單：點外面、Esc 關閉，方向鍵移動，目前所在那一項亮起。
- 會員選單的「雷諾曼」一組只放紀錄（D8）。

### 共用的占卜流程（階段 4）
- 三步驟流程從 `HomeView` 抽成 `useReadingFlow`，塔羅與雷諾曼各自傳入 API 與設定；`useDrawState`、`StepDraw`、`StepQuestion`、`SpreadSlots`、`SpreadLayout`、`FanDeck` 改成兩套牌都能用（牌的型別是泛型）。
- 正逆位改成選配：沒有正逆位的牌組不轉向、不顯示正逆位、不能切換。
- 選牌器的分組搬到 `lib/cardGroups.ts`（塔羅：大牌／花色；雷諾曼：1～36、37～52，可以用牌號搜尋）。
- 塔羅不受影響：和改動前的 main 並排跑同一套流程（問題、扇形、輸入、自動、結果），畫面結構逐項一致。
- 回歸測試抓到的錯：Vue 會把沒傳的選填布林 prop 當成 `false`，塔羅沒傳 `orientations` 就少了正位按鈕、`allowFreeSpread` 少了「不指定牌陣」。改成 `withDefaults` 給預設值，並在 `check-rules` 加規則 `boolean-prop-absent`（`props.xxx !== false` 會被擋）。

### 雷諾曼占卜（階段 4、5）
- `LenormandView`：問題類型不含股市、多了健康與家庭；「代表我的牌」（紳士／淑女，大藍圖必填）；抽牌方式照牌陣的 `drawModes`。
- 牌面是後端的原創 SVG，`cardImageUrl` 遇到 `/lenormand/` 直接用原圖、不經過像素引擎；開發時 Vite proxy 只轉 `^/lenormand/.+`，`/lenormand` 頁面重新整理不受影響。
- 花園藤蔓的牌背（`pixelArt.ts` 的 `installLenormandCardBack`），離開雷諾曼頁換回塔羅的牌背。
- 結果頁 `LenormandResult`：排列圖、逐張牌義（`/cards` 快取）、組合分析（後端文字照順序顯示）、撲克花色獨立一區（解說表可收合）。問題類型對應的 L8 主題牌在畫面上叫「關鍵牌」，避免和主題牌陣中間的「主題牌」位置混在一起（前後端已統一）。
- 大藍圖 `GrandTableau`：9×4，一格一個宮位；中心（代表牌）與關鍵牌加框，沒出現時在它們的宮位標出來。距離／騎士跳／鏡射三種看法，點一格看第幾宮、離中心多遠、方位、牌義與宮位主題。分組與落點都用後端算好的結果，前端不重算。
- 大藍圖的手機版：結果頁整張縮到一個畫面寬（要看整體的位置關係），輸入頁左右捲動（要看得到宮位與牌名）；兩種都截圖比較過。
- 輸入實體牌：大藍圖用 9×4 格子逐格選，可以選完自動跳到下一格，選牌器標示「已在第 N 格」。
- 背景：雷諾曼頁的背景和塔羅首頁一樣（夜晚的像素城市），兩個路由共用 `sceneBus.ts` 的 `DIVINATION_SCENE`，步驟對背景的反應用共用的 `useSceneSync`。原本設成 interior（酒吧室內），使用者要求改。

### 紀錄、月曆、日記、帳號設定（階段 6）
- 結果頁「保存紀錄」，手感比照塔羅；只存牌號、問題、牌陣、代表牌與完整寫完的解讀，分析讀取時由後端重算。
- 雷諾曼紀錄 `/lenormand/records`：沿用 `HistoryView` 的分頁機制（`recordTabs: ['lenormand']`），清單用 `RecordListShell`＋`RecordIndex`，詳情用同一個結果元件（大藍圖也能顯示），刪除用 `confirmDialog`。
- 月曆當天的占卜依 `deck` 連到塔羅或雷諾曼紀錄，雷諾曼加小標；舊版後端沒有 `deck` 時一律當塔羅。
- 日記可以寫在雷諾曼紀錄底下（`/journal/lenormand/<id>`），返回連結與文字依種類決定。
- 帳號設定加「刪除我的雷諾曼紀錄」：有紀錄或日記才出現，刪除前先確認；給被收回權限、看不到紀錄清單的人清掉自己的資料。讀不到筆數（舊版後端）就整塊不顯示。

### AI 解讀（階段 7）
- `streamLenormandNarration`：寫法照塔羅的 `streamNarration`（自己帶 Authorization、心跳判斷斷線）；403、429、422、503 顯示後端的訊息。
- `useLenormandNarration`：一次一個請求、過期回應丟掉、可以停止、離開頁面中斷計費；占卜頁與紀錄頁共用。
- 保存的先後順序：先保存再解讀，帶紀錄 id 讓後端存回；解讀先寫完，自動連同解讀保存（同塔羅）；解讀寫到一半按保存，等寫完再一起存（後端沒有事後補存解讀的 API），停止或失敗就只存牌。
- 紀錄頁可以補做或重新產生，照紀錄存下的問題類型送（後端要一致才存回）；日記頁只看不能產生。
- 管理端會員詳情多一列「雷諾曼 AI 解讀」用量。
- 只用前端模擬的串流測過，沒有實際呼叫 AI。
