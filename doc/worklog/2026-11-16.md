## 2026-11-19

### AI 解讀的回饋（配合後端 v25 階段 4）
- 新元件 `NarrationFeedback`：AI 解讀與追問回答寫完後，下面多一列「有幫助／沒幫助」；按沒幫助可以選原因（沒回答到問題、太籠統、時間不對、太長、其他），再按一次是取消。只有已經是紀錄時才顯示（AI 解讀寫完會自動保存，所以登入後就有）。
- 重新產生或重新回答後是新的一篇，回饋從頭來；「我的紀錄」打開時顯示當時的回饋。
- 新的型別與 API：`NarrationFeedback`、`NARRATION_FEEDBACK_REASONS`、`updateNarrationFeedback`；`SavedNarration.feedback`、`followUpNarration.feedback` 為可選（舊版後端沒有，就當成還沒回饋）。
- 驗證：`npm run build` 通過，沒有新增套件。

### 待辦
- 部署後在手機上按一次回饋：按鈕換行的位置、選原因後顯示「謝謝，已記下」。
- 使用者回報兩個追問的問題（同日）：
  - 最新的追問還沒有 AI 回答，「這次的回答有幫助嗎？」就先出來了：改成每一次追問都有回答才顯示。
  - 追問抽完牌、按 AI 回答後，畫面往下跑、看不到剛才的追問。原因是新內容插在眼前的牌堆和按鈕上面，瀏覽器的捲動錨定讓眼前的元素維持在原位，新內容就被推到畫面上方。改成抽完、開始回答時捲到那一次追問的開頭（`scrollToRound`）。ui-check 補了這兩條。
- 追問抽完牌直接請 AI 回答，不用再按「請 AI 回答新的追問」（使用者要求）。沒開通或沒登入時照舊停在按鈕；上一篇回答還在寫時不會插隊，等寫完再按。
- 配合後端的自訂位置分組：`RelationKind` 加 `group`（判斷依據的牌對顯示「──同組──」）。`npm run build` 通過。
- 配合後端的建議題：是非判斷的 `yesMeans` 型別加 `advice`（可選值，舊版後端不會出現）。判斷依據裡的宮廷牌、數字階段文字由後端改寫，前端不用改。`npm run build` 通過。
