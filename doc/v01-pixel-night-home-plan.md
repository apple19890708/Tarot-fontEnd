# v01　像素風首頁：星夜城市與居酒屋

建立日期：2026-11-02
狀態：背景（階段 1～5）、互動像素化（階段 7～11）、全站場景與過場（階段 13～18）、像素牌面（階段 20～21）實作完成，待使用者驗收；CPU 實測還沒做

## 一、目標

把首頁（`src/pages/HomeView.vue`，塔羅占卜第一頁）的背景，從現在的漸層加兩團模糊光暈
（`src/style.css` 的 `:root` 背景與 `body::before／::after`），換成一幅會動的像素風夜景，
當作之後全站換風格的範例頁。

畫面內容（由上到下、由遠到近）：

1. **星夜**：深藍到紫的夜空，零星星星，少數會閃。
2. **下弦月**：左半邊亮的月亮（北半球看到的下弦月是左半亮），帶一圈淡光暈。
3. **少量雲朵**：兩到三朵像素雲，非常慢地往左飄，偶爾經過月亮前面。
4. **燈火通明的高樓**：遠近兩層天際線，窗戶多數亮著暖黃色，少數隨機明滅；遠層顏色較暗，做出景深。
5. **右下角日式居酒屋**：木造小店面，門口掛暖簾和紅燈籠，招牌寫「居酒屋」，窗內透出暖光，燈籠輕微晃動。
6. **地面路人**：三到六個小人在人行道上左右走，有走路動畫，經過居酒屋時偶爾停下。

**不做的事**（這一版明確不碰）：

- 不重畫 78 張牌面，牌卡、牌陣、解讀維持現有樣式。
- 不改解讀內文的字型，長文用像素字很難讀；像素字只用在標題、步驟列、按鈕。
- 不改其他頁（登入、紀錄、管理）。等首頁定案再另開一版決定要不要全站套用。
- 不做可以操作的遊戲互動（例如控制角色、點路人觸發對話）。這一版只做「會動的背景」，
  加上滑鼠移動時的輕微視差。
- 不加音效。
- 不找外包美術。第一版的圖全部用程式畫，之後要換成手繪素材時，介面已經預留好（見 2.4）。

## 二、規格

### 2.1 技術選擇與評估

| 方案 | 做法 | 優點 | 缺點 | 新套件 |
|---|---|---|---|---|
| 2026-11-03 | 像素牌面接進網站，可在導覽列切換原版／像素；引擎動態載入、依圖片檔名對應 | 使用者驗收完整副 78 張後要求替換並可切換；檔名規則固定，不必改後端 |
| 2026-11-03 | 小牌改成逐張情境畫面（權杖→錢幣→寶劍→聖杯），不用牌點排列 | 使用者：「這樣不對我要情境」 |
| **A. Canvas 2D（建議）** | 一個全螢幕 `<canvas>`，用低解析度畫，再放大顯示 | 不用裝東西；像素風本來就是低解析度，效能很輕；完全可控 | 要自己寫一個小小的繪圖迴圈 | 無 |
| B. PixiJS | 用 WebGL 遊戲引擎畫 | 素材多、特效（光暈、粒子）容易做 | 套件約 400KB 以上，對一張背景來說太重 | 要裝 `pixi.js` |
| C. 純 CSS／SVG | 每棟樓、每個路人都是 DOM 元素 | 不用寫繪圖迴圈 | 窗戶、星星、路人加起來上千個元素，手機會卡；很難做出真正的像素邊 | 無 |

**建議用 A**。理由：

- 專案規範不隨意加套件。A 不需要新套件，B 要先徵求同意。
- 現有的 `gsap` 已經裝了（`FanDeck.vue` 在用），A 若需要補間動畫，例如路人停下再走，可以直接借用，不算新套件。
- 像素畫的核心技巧就是「用很小的解析度畫，再整數倍放大」，Canvas 天生適合。

### 2.2 會用到的技術

| 技術 | 用在哪裡 |
|---|---|
| `<canvas>` + Canvas 2D API | 畫整個場景 |
| 低解析度畫布（例如 320×180）＋ CSS `image-rendering: pixelated` | 放大時不模糊，保持方塊感；在 Tailwind 寫成 `[image-rendering:pixelated]` |
| `requestAnimationFrame`，限制在每秒 12 格 | 像素動畫刻意低格數才有味道，也省電 |
| 固定亂數種子 | 每次打開，窗戶怎麼亮、星星在哪裡都一樣，畫面不會每次重新洗牌 |
| `document.visibilitychange` | 切到別的分頁就暫停動畫，回來再繼續 |
| `prefers-reduced-motion` | 系統設定減少動態時，只畫一張靜態畫面 |
| `ResizeObserver` | 視窗大小改變時，重算畫布尺寸與放大倍數 |
| Vue 3 `<script setup>` 元件 | 場景包成一個元件，在 `onMounted` 啟動、`onBeforeUnmount` 停掉，不留下計時器 |
| 像素中文字型（自帶字型檔，不是套件） | 標題、步驟列、按鈕；候選「俐方體 11 號（Cubic 11）」、「縫合像素（Fusion Pixel）」，都是 OFL 授權可商用 |

字型要注意：完整的中文像素字型約 2～5MB。做法是**只抽出首頁用到的字**，做成很小的字型檔，
放在 `public/fonts/`，路徑用 `import.meta.env.BASE_URL` 組，不要寫死開頭的 `/`。
抽字可以用 Python 的 `fonttools`（本機已有 Python）。這是一次性的處理工具，不進前端的 `package.json`。

| 層 | 內容 | 動態 | 視差（滑鼠移動時） |
|---|---|---|---|
| 1 天空 | 由上到下的深藍→紫漸層，用 3～4 階色塊做出像素漸層，不用平滑漸層 | 無 | 0 |
| 2 星星 | 約 40 顆，1～2 像素 | 約 1/5 會慢慢閃 | 最小 |
| 3 月亮 | 下弦月，直徑約 16 像素，外圍 1 圈淡光 | 無 | 小 |
| 4 雲 | 2～3 朵，深灰紫色，邊緣有 1 像素較亮的描邊 | 每秒往左移約 1 像素，出畫面後從右邊回來 | 小 |
| 5 遠樓 | 低矮、顏色偏暗的天際線，窗戶小而少 | 偶爾一扇窗亮或滅 | 中 |
| 6 近樓 | 較高、較亮，窗戶多數亮著暖黃色，少數冷白色 | 同上，頻率較高；屋頂紅色航空燈閃爍 | 中大 |
| 7 居酒屋 | 固定在右下角：瓦屋頂、木格窗、暖簾、2 盞紅燈籠、直式招牌「居酒屋」 | 燈籠輕晃、窗內光微微閃 | 大 |
| 8 地面 | 人行道、路燈 | 路燈下有光圈 | 大 |
| 9 路人 | 3～6 人，每人 8×16 像素，4 格走路動畫；衣服顏色隨機 | 左右走，速度不同；走到居酒屋前有機率停 1～2 秒 | 大 |
| 10 前景暗角 | 畫面四邊加深，讓中間的占卜卡片更突出 | 無 | 0 |

畫面上要留出**中間偏上的空區**，給現有的占卜卡片。場景的重點（月亮、居酒屋、路人）都放在邊緣與下方，
不跟卡片搶。

### 2.4 素材怎麼來

- **第一版：全部用程式畫**。窗戶、樓、雲、路人都是用小方塊組出來的。好處是馬上看得到效果，也不用等美術。
- **之後可換成手繪圖**：每個物件都設計成「先找有沒有圖，沒有才用程式畫」。
  要換的時候，把 PNG 素材（例如居酒屋 64×48、路人 4 格動畫圖）放進 `public/pixel/`，不必改繪圖邏輯。
- 繪製工具建議 Aseprite（付費）或 Piskel（免費、網頁版），之後真的要手繪時再評估。

### 2.5 跟現有畫面的關係

- 首頁才顯示這個場景；其他頁維持原本背景。做法是把場景元件放在 `HomeView.vue` 最外層，
  `position: fixed`、放在 `#app` 內容後面；同時把 `body::before／::after` 的光暈在首頁關掉，避免疊兩層光。
- 占卜卡片（`section`）維持深色玻璃，但背景透明度要調高一點（例如 `bg-slate-950/45` 改 `/65`），
  否則後面的窗戶燈光會干擾閱讀。改動限在首頁。
- 標題「塔羅占卜」和步驟列換成像素字；步驟膠囊的圓角改成方角加 2 像素實線框，做出像素按鈕感。
  這是首頁限定的樣式，不動共用元件。

### 2.6 手機與效能

- 畫布內部固定高 180 像素，寬度依螢幕比例算；放大倍數取整數（例如 4 倍、5 倍），保持像素方正。
- 手機直向時畫面很窄：天際線往左延伸被裁掉，**居酒屋固定貼右下角不被裁**，路人減為 3 人。
- 每秒 12 格、畫布只有幾萬個像素，預估手機 CPU 占用很低；完成後用瀏覽器效能面板實測一次。
- 分頁切走時暫停；開了減少動態就只畫一張靜態圖。

### 2.7 延伸：占卜流程帶入像素效果（2026-11-02 追加，階段 7～12）

背景做完後，占卜流程本身（步驟 1 寫問題、步驟 2 抽牌、步驟 3 看結果）還是深色玻璃風：
圓角、模糊陰影、平滑動畫。這一段讓互動也有像素感，並讓夜景跟著占卜流程反應。

涉及的元件：`StepQuestion.vue`、`StepDraw.vue`、`FanDeck.vue`、`FlyingCard.vue`、`SpreadSlots.vue`、
`StepResult.vue`、`HomeView.vue`、`PixelNightScene.vue`。

**這一段也不做的事**：不改解讀長文（牌義、組合分析、AI 解讀）的字型；不改問題輸入框的字型
（內容無法預先抽字）；不改其他頁；不手繪牌面，只試程式自動像素化；不加音效、不加新套件。

#### 2.7.1 介面外框像素化（只換 Tailwind class）

| 現在 | 改成 |
|---|---|
| `rounded-full`、`rounded-3xl`、`rounded-[1.5rem]` | 方角（拿掉 rounded） |
| `border` 1px 半透明 | `border-2` 實線，顏色用場景色盤裡的實色 |
| `shadow-[0_25px_70px_...]` 模糊陰影 | 硬邊投影 `shadow-[4px_4px_0_#000]` |
| `backdrop-blur`、`blur-lg` | 拿掉 |
| 按鈕 hover／active 變亮 | 加上按下時 `translate-x-[2px] translate-y-[2px]`，同時投影縮小，做出壓下去的手感 |

範圍：牌陣選擇、抽牌模式切換、送出、重新開始等按鈕，三個步驟的外框卡片、提示框。
不動共用的 `SelectField`、`SkeletonBlock`。

#### 2.7.2 字型

- **用像素字**：按鈕、標籤、牌名、正逆位、牌陣位置名稱、步驟標題。
- **維持原字型**：問題輸入框、牌義與解讀長文、錯誤訊息（錯誤要讀得清楚）。
- 字型檔要重新抽字：加入 78 張牌名、牌陣位置名稱、按鈕文字。抽字清單由一支小腳本
  從前端程式與後端牌名產生，避免漏字（漏掉的字會退回 Noto Serif TC，混在一起很明顯）。
  預估檔案從 3KB 增加到幾十 KB，屆時不會再被內嵌進 CSS，路徑仍由 Vite 套 base。

#### 2.7.3 動畫逐格化

- `FanDeck.vue`、`FlyingCard.vue` 的 `gsap` 緩動從 `power1／power2` 改成 `steps(n)`，n 約 4～8。
  時間長度不變，只是從平滑變成一格一格跳。
- 步驟切換的 `Transition`：淡入改成逐格（`[transition-timing-function:steps(4)]`），
  位移距離改成像素的整數倍。
- `prefers-reduced-motion` 的既有處理保留。

#### 2.7.4 牌卡

- **牌背**：用 Canvas 畫一張像素牌背（深藍底、星星與彎月紋樣，配色取自夜景），
  取代現在 `from-indigo-950 via-slate-900 to-purple-950` 的漸層。
- **牌面像素化**：把後端給的牌圖畫到很小的畫布（例如寬 32 格）再放大，用
  `[image-rendering:pixelated]` 顯示。只縮放不讀取像素，所以不受跨網域圖片限制。
  先做成可切換的選項，比較原圖與像素化的效果再決定。
- **翻牌**：改成 3～4 格逐格動畫，牌從正面縮成一條線再翻開，取代平滑翻轉。

#### 2.7.5 夜景跟著流程反應

`HomeView` 把「目前步驟」和「抽牌事件」傳給 `PixelNightScene`（props），場景依狀態切換：

| 時機 | 夜景反應 |
|---|---|
| 步驟 1 | 正常夜晚 |
| 進入步驟 2（開始抽牌） | 高樓窗戶在 2 秒內陸續暗下，只剩居酒屋、路燈、月亮亮著 |
| 每抽出一張牌 | 一顆流星由右上往左下劃過（約 1 秒） |
| 抽到逆位 | 一朵雲移到月亮前面停 2 秒再離開 |
| 進入步驟 3（結果） | 窗戶在 2 秒內陸續亮回來；路人停下 1 秒再走 |
| 重新開始 | 回到正常夜晚 |

場景只吃事件、不回傳任何東西，占卜邏輯不受影響。「減少動態」時只切換明暗，不做流星和雲的動畫。

### 2.8 延伸：全站場景與頁面過場（2026-11-02 追加，階段 13～19）

首頁之外的頁面也換成同一個像素世界的不同角落，換頁時用「鏡頭移動」接起來，像在同一條街上走動。

#### 2.8.1 每頁的場景

| 頁面 | 場景 | 畫面內容 | 動態 |
|---|---|---|---|
| 占卜（首頁） | `city` 街景 | 現有的星夜、高樓、居酒屋、路人 | 現有的全部 |
| 登入、註冊 | `door` 居酒屋門口近景 | 暖簾、兩盞紅燈籠、拉門的木格與門內暖光、門前一小段人行道 | 燈籠晃、暖簾偶爾被風吹動、偶爾有路人從門前走過 |
| 我的紀錄 | `interior` 居酒屋店內 | 木吧檯、吧檯後的酒瓶架、掛燈籠、幾張高腳椅、入口的拉門 | 服務生偶爾端菜放上吧檯；客人零星從入口進來坐下、過一陣子離開 |
| 路由管理、會員管理 | `sky` 星夜 | 夜空、星星、彎月 | 偶爾一朵雲飄過、偶爾一顆流星 |

場景由路由設定指定：`meta.scene`，沒寫的頁面預設 `sky`（最安靜）。

#### 2.8.2 頁面過場（鏡頭）

| 從 → 到 | 過場 | 長度 |
|---|---|---|
| 門口 → 街景（登入後回占卜） | 從門口近景**慢慢拉遠**，鏡頭停在居酒屋，再退到整條街 | 約 1.6 秒 |
| 門口 → 店內（登入後進我的紀錄） | 暖簾被撥開、拉門往旁邊滑開、鏡頭往前推進門裡，店內淡入 | 約 1.8 秒 |
| 街景 ↔ 星夜（占卜 ↔ 管理頁） | 街景**整片往下沉**、鏡頭往上搖，只剩夜空；反方向就是往下搖回街上 | 約 1.2 秒 |
| 店內 → 街景（紀錄 → 占卜） | 走出店門：店內淡出成門口，再拉遠到整條街（門口 → 店內的反向） | 約 1.8 秒 |
| 街景 → 門口（占卜 → 登入） | 鏡頭推近居酒屋門口（門口 → 街景的反向） | 約 1.6 秒 |
| 其他組合 | 快速交叉淡化 | 約 0.4 秒 |

- 過場時鏡頭的移動也用逐格（`steps`），和整站的像素動畫一致。
- 過場中再點別的頁面：直接跳到上一個過場的終點，再開始新的過場，不會疊在一起。
- 「減少動態」時不播過場，直接切換。
- 頁面內容（表單、清單）在過場的後半段才淡入，避免文字跟著鏡頭晃。

#### 2.8.3 技術做法

- **場景元件搬到 App 層**：現在的 `PixelNightScene` 掛在首頁裡，換頁就被拆掉，接不起過場。
  改成 `App.vue` 底下常駐一個 `PixelWorld`，依目前路由的 `meta.scene` 決定畫哪個場景、換頁時播哪段過場。
- **一個鏡頭，多個場景**：每個場景是一個「畫自己」的模組（`city`、`door`、`interior`、`sky`），
  共用時間、亂數、低解析度畫布。鏡頭有位置與縮放，過場時用 `gsap`（已安裝）補間。
- **縮放的像素問題**：低解析度場景直接放大到 3～4 倍，像素會變成一大塊、和其他場景的格子大小不一致。
  所以「街景推近到門口」時，前半段放大街景，後半段**交叉淡化**到另外畫好的門口近景（門口有自己的細節），
  終點的格子大小和其他場景一樣。店內同理。
- **其他頁的卡片底色**：全站都有背景後，登入、紀錄、管理頁的卡片也要改成首頁的 90% 不透明，
  否則表格和表單會被背景干擾。`App.vue` 外層不再上 `bg-neutral-900`。
- 不加新套件。

#### 2.8.4 我的紀錄：木製菜單板

左側的紀錄清單（`ReadingHistoryIndex.vue`）設計成居酒屋牆上的**木製菜單板**：

- 外框是深色木框，裡面是木板底，用程式畫一張木紋小圖，和牌背一樣放進 CSS 變數共用。
- 每一筆紀錄是一塊掛在板上的木牌：日期、牌陣、問題摘要。選中的那塊微微突出、邊緣亮一點。
- 標題、日期用像素字；問題摘要等長字維持原字型（同 2.7.2 的原則）。
- 右側的紀錄內容維持現在的版型，只換成 90% 不透明的卡片底。

#### 2.8.5 這一段不做的事

- 不加音效（開門聲、店內人聲）。
- 店內的人物不能點、不能互動。
- 不為每個頁面做專屬場景以外的變化（例如依時間變成白天）。
- 手機上過場照樣播，但店內的客人數量減半。

#### 2.8.6 待使用者確認

1. 從**不是登入頁**的地方直接進「我的紀錄」（例如已登入，從占卜頁點過去）：要不要也播「走到門口 → 開門進去」？建議要，路線是街景先推近門口，再接開門。
2. 從「我的紀錄」回占卜頁：要播「走出店門 → 拉遠到街上」嗎？建議要。
3. 菜單板的樣子：**原木色木牌、深色字**（像店裡掛的品名牌），還是**深色黑板、白色粉筆字**？
4. 過場長度 1.2～1.8 秒可以嗎？常常換頁的人可能會嫌慢，可以縮短到 0.8～1 秒。

### 2.9 延伸：像素版牌面與切換（2026-11-03 追加，階段 20～21）

先在展示頁（artifact）畫完整副 78 張，使用者逐張驗收後才接進網站。原本 2.7.4 試做的「把原圖縮小再放大」被否決，這次改成每張重新構圖。

1. **畫法**：80×128 格、共用 30 色色盤（每張 13～27 色）、Bayer 4×4 抖色、背景層與角色層分開、角色層自動描深色外框、光源固定左上。
2. **構圖**：
   - 大牌照 Rider-Waite 的象徵，每張的關鍵元素列在展示頁上。
   - 小牌四個花色（權杖、錢幣、寶劍、聖杯）的 1～10 都是情境畫面，不是只排牌點。
   - 宮廷牌是同一套侍者／騎士／皇后／國王畫法，換花色顏色，再加上各自的象徵物。
3. **接入網站**：
   - 引擎放在 `src/lib/pixelTarot/engine.js`。它是 JS，型別宣告在 `engine.d.ts`。
   - 對應方式：用後端圖片檔名（`major-NN`、`wands-NN`…，11～14 是侍者到國王）對到牌。
   - 輸出：放大 4 倍、上下補透明成 7:12 的 data URL，元件裡的 `object-cover` 不會裁到牌框。
4. **切換**：
   - `src/lib/cardStyle.ts` 管原版／像素，記在 localStorage。元件一律用 `cardImageUrl()` 取牌面。
   - 引擎只在切到像素版時才動態載入，約 63 KB，打包後是獨立檔。載入前或載入失敗，就先顯示原版。
   - 切換鈕是浮在畫面右上（導覽列下方、捲動時也在）的方形像素 icon 開關（牌框裡排著像素方塊），開著時亮琥珀色。演變：導覽列兩顆文字按鈕 → 一顆文字開關 → 導覽列 icon → 使用者要求改成浮動按鈕。
5. **不做的事**：
   - 不改後端，也不產生圖片檔進 repo。牌面在瀏覽器即時畫，每張畫一次就快取。
   - 牌背維持 2.7.4 的像素牌背，兩種風格共用。

### 全站場景與過場實作紀要（2026-11-02）
